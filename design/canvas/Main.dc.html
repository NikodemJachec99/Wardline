Six rules the interface must make obvious

Each rule is owned by specific components

Scan opens. It never moves.

A wristband or QR scan only identifies and opens the patient. A transfer is a second, separate sheet with its own Confirm.

WlBottomSheet · WlTransferPath

Your role shapes the actions

Nurses see Transfer. Doctors see Change status. An action a role can't take is absent, never shown disabled.

WlPatientCard · WlButton

Location and status never merge

Where a patient is and what state they are in are two fields, two rows, two components. Status always pairs colour, icon and text.

WlStatusChip · WlTransferPath

Confirmed, not assumed

While the server works, the button shows a spinner and locks. The checkmark appears only after the server confirms.

WlButton · WlToast

Offline is read-only

Cached records stay browsable, labelled as possibly outdated with the last sync time. Every edit action is removed until reconnect.

WlOfflineBanner · WlCacheBadge

Conflicts are spelled out

If someone moved the patient first, show who, from where to where, and when, then ask to refresh. Never a silent retry.
